# Brief a bounded task

Locate the current brief and relevant decisions before asking the user to repeat them. Fill this from supplied evidence; distinguish proposals from facts. For a small, clear request, the task and check can fit in one sentence.

```markdown
# Task brief
Outcome and audience:
Source of truth and useful files:
Existing decisions to preserve:
Scope and exclusions:
Constraints with reasons:
Deliverable and intended use:
Observable acceptance checks:
Material unknowns and assumptions:
Next action:
```

For a design task, include the actual reference, approved assets, platform, key user task and review criteria. For research, include the question, date range and evidence standard. For implementation, include the relevant interface, current behavior and a way to verify the change.

If an answer would materially change the solution and cannot be found, ask one concise question or a small set of choices. Continue independent preparation while waiting. Do not add an approval stage for an already authorized routine action.

When a concept is open, compare distinct options on fit, evidence, effort and limitations. Choose one direction before expanding it; a fixed number of alternatives is not necessary.
