## Runtime and access

Adopted files are instructions loaded when relevant. They do not connect accounts or grant permissions. No upstream installer, server, update check, generator, browser connection, scheduled job or paid tool was run. No runtime cost or productivity gain was measured. Existing client systems, provider/model choices and task scope retain authority.

The optional Awwwards runtime may fetch public award/site data, visit candidate sites, keep a local SQLite/image cache and check the package registry. Its build tool writes files. Optional CDP and auto-update settings need a separate review before setup. See [Awwwards research](awwwards-research.md).

## Bounded applied checks

Instruction routing was reviewed against six scenarios: screenshot-only review; equal-valued gap/radius tokens; screenshot-only dimensional spec; palette refresh with logo/type kept; public Awwwards research without MCP; animated measured sheet. These are static self-review scenarios, not observed client projects or executed design tests.

For a real pilot, choose one component from an authorized project. Trace its dimension table to tokens/code, render it, inspect the drawing and test the relevant task separately. Keep unknowns visible. Only then record practical usefulness.
