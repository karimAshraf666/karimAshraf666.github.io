# Portfolio navigation

## 1. Requirements
Purpose: keep work, personal context, contact and the reusable workbench reachable.
Anatomy: header, brand link, Workbench link, menu toggle, navigation links.
- F1: The Workbench link reaches workbench.html from every root content page.
- S1: The Workbench link has a distinct cobalt treatment without animation.
- B1: The menu toggle opens and closes navigation links on mobile.
- B2: Escape closes mobile navigation links and focuses the menu toggle.
- C1: The label stays Workbench.
- A1: The Workbench link remains visible at 390px when navigation links are collapsed.
- A2: The header fits the viewport at 320px and 390px.
- A3: Each link has a visible focus state.
- I1: Preserve resume and contact destinations.
Out of scope: resource category state, owned by Workbench navigation.
Ruled out: pulsing badges and a New label. Karim requested prominence, not a recency claim.

## 2. Design notes
Use the existing palette. Keep the mobile Workbench link outside the collapsible navigation, with a geometric decorative mark and a plain text label. See discovery tokens.
## 3. Pre-dev research
The shared shell is generated by portfolio_shell.py. Root pages must receive the same shell, with their current-page semantics retained. Existing menu behavior in script.js already handles Escape.
## 4. Usage guidance
Use on all root portfolio pages. Keep the workbench as a utility alongside case studies.
